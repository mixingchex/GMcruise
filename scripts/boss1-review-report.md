### 5. 권장 테스트 워크플로우 (채민관 CTO 전략)

```
1. 특정 기능에서 버그 발견
   ↓
2. 해당 기능만 격리하는 테스트 코드 작성
   (예: scripts/test-feature-name.ts)
   ↓
3. 입력/출력 검증 (Input/Output)
   ↓
4. 문제 재현 및 수정
   ↓
5. 테스트 코드로 수정 확인
   ↓
6. 실제 환경에 적용
```

## 코드 품질 개선 제안

### 격리된 기능 테스트의 장점
1. **빠른 디버깅**: 로그인 등 불필요한 단계 제거
2. **명확한 검증**: 각 기능의 입출력만 집중
3. **재사용 가능**: 회귀 테스트로 활용
4. **AI 친화적**: AI가 전체 맥락 없이도 특정 기능 수정 가능
